# Chapter 00. 개발 환경 구성

## 1. 학습 목표
Java 21과 Spring Boot 애플리케이션을 실행하고, Docker Compose로 Kafka와 Redis를 준비한다. 이 프로젝트의 모든 예제는 이 개발 환경을 공통 기반으로 사용한다.

## 2. 구성 요소와 역할

| 구성 요소 | 역할 | 기본 주소 |
|---|---|---|
| Spring Boot | REST API와 비즈니스 로직 실행 | `http://localhost:8080` |
| Kafka | 비동기 이벤트 전달 | `localhost:9092` |
| Redis | 캐시·카운터·임시 데이터 저장 | `localhost:6379` |
| Swagger UI | API 호출 및 명세 확인 | `/swagger-ui.html` |

## 3. 실행 순서

```bash
docker compose up -d
docker compose ps
mvn spring-boot:run
```

애플리케이션을 종료할 때는 `Ctrl+C`, 인프라를 종료할 때는 `docker compose down`을 실행한다. Redis 볼륨까지 삭제하려면 `docker compose down -v`를 사용한다. 이 명령은 로컬 Redis 데이터를 삭제하므로 주의한다.

## 4. 설정 흐름

- `pom.xml`: Spring Web, Spring Kafka, Spring Data Redis, Validation, springdoc 의존성을 선언한다.
- `application.yml`: Kafka 브로커와 Redis 접속 정보를 환경 변수로 덮어쓸 수 있게 한다.
- `docker-compose.yml`: 로컬 학습용 Kafka 단일 브로커와 Redis를 실행한다.
- `DemoApplication`: Spring Boot 자동 설정과 컴포넌트 스캔의 시작점이다.

## 5. 연결 확인

```bash
curl http://localhost:8080/actuator/health
curl http://localhost:8080/v3/api-docs
```

Kafka/Redis 접속 장애가 발생하면 컨테이너 상태, 포트 충돌, 환경 변수(`KAFKA_BOOTSTRAP_SERVERS`, `REDIS_HOST`, `REDIS_PORT`)를 먼저 확인한다.

## 6. 운영 환경 주의사항
현재 Compose 설정은 로컬 개발 전용이다. 운영 환경에서는 Kafka 다중 브로커, 인증·TLS, Redis 인증 및 네트워크 격리, 비밀정보 관리, 모니터링과 백업을 별도로 구성해야 한다.
